# Freebuff — контроллер мультиинстанса

**[中文](README.zh-CN.md) · [English](README.en.md) · [Русский](README-RU.md)**

Небольшая утилита для Windows, которая позволяет запускать несколько экземпляров настольного приложения [Freebuff](https://www.freebuff.com) одновременно — каждый со своим независимым аккаунтом.

> Чисто сторонняя утилита: само приложение Freebuff она не изменяет и с официальным Freebuff никак не связана.

## Что изменено в этой вилке

Ветка `ru` — форк оригинала на теге `v1.9.7`. Функциональных изменений нет, только локализация и вёрстка:

- Весь интерфейс переведён на русский, шрифт `Segoe UI`.
- Главное окно расширено 580 → 660 px, веса колонок `13/14/40/33` → `20/20/30/30` — колонки «Слот» и «Статус» больше не обрезаются.
- Шрифты приведены к стандартным 9 pt.
- Статусы сокращены до `● Вкл` / `○ Выкл`.
- Правило языка в `~\.AGENTS.md` пишется на русском: AI отвечает по-русски независимо от языка запроса.
- Китайский пакет локализации (`hanhua/`) в сборку не входит. Логика автовосстановления осталась в коде, но без каталога `hanhua/` она молча ничего не делает.

## Возможности

- **Мультиинстанс**: главный экземпляр плюс слоты 1–9, не мешают друг другу. Повторный двойной клик по ярлыку не выдаст «уже занято» — уже запущенное окно просто выведется на передний план.
- **Мультиаккаунт**: у каждого экземпляра свой профиль Chromium и своё состояние входа, поэтому можно войти под разными аккаунтами; кнопка «Сбросить аккаунт» меняет номер.
- **Общие сессии** (включено по умолчанию): все слоты используют одну историю чатов — когда квота аккаунта A кончилась, окно аккаунта B открывает ту же историю и продолжает разговор, копировать и выбирать сессию не нужно.
- **Квота**: по каждому аккаунту показывается **Freebucks** — остаток за сегодня и общий лимит, при наведении видны баланс кошелька и цена. С v1.9.6 аккаунты опрашиваются **параллельно** (сам интерфейс квоты медленный, последовательный опрос складывался в минуты); **без прокси весь обход пропускается** — прямых обращений «втихую» не будет.
- **Ответы на русском по умолчанию**: при запуске автоматически записывается языковое правило в `~\.AGENTS.md` (с защитой от инъекций), поэтому AI отвечает по-русски независимо от языка запроса.
- **Сеть и прокси**: проверка обновлений, загрузка установочных пакетов и запрос квоты идут по цепочке «локальный прокси → системный прокси → прямое подключение»; удачный маршрут запоминается. Локальный прокси определяется по распространённым портам (функциональной проверкой, «мёртвый» прокси тоже распознаётся). Вверху окна есть «Прокси» — сменить адрес, отключить или оставить пустым для автоопределения; при обрыве связи выскакивает уведомление, какой именно слот и какой адрес отвалились.
- **Мало лишних кнопок**: сверху только «Удалить сессии» и «Прокси», в трее осталось лишь «Выход» — очистка, обновления и квота работают автоматически.
- **Остановка сначала по-хорошему**: слот сначала просят завершиться штатно (до 2 секунд, чтобы SQLite успел закрыться), потом процесс убивается вместе со всеми дочерними.
- **Лог сбоев**: ошибки на критичных путях (замена файлов, завершение процесса, запись `state.json`, создание junction, вывод окна) пишутся одной строкой в `%TEMP%\freebuff-controller-log.txt` — интерфейс не засоряется, но если «двойной клик ничего не сделал», есть на что посмотреть.
- **Удаление сессий**: можно удалить сессию вместе со всей историей (в самом Freebuff есть только «архив»).
- **Автоочистка установочных пакетов**: кэш electron-updater и осиротевшие пакеты в `%TEMP%` чистятся автоматически.
- **Проверка обновлений**: показывает установленную версию Freebuff и, если есть новая, даёт скачать официальный установщик (запускается только при наличии корректного SHA512). Сам контроллер тоже умеет обновляться из Release этого репозитория.
- **Интерфейс**: белая простая версия с v1.9.0 плюс плавные переходы; один файл exe (~195 КБ, без зависимостей), сворачивается в трей.

## Использование

1. Запустите `FreebuffController.exe` из [Releases](https://github.com/Dima-Sor/freebuff-controller/releases) или соберите сами — см. ниже.
2. Дважды щёлкните по неинициализированному слоту (или выделите его и нажмите «Запуск») и в окне выберите «Новый вход».
3. Войдите в аккаунт в открывшемся окне Freebuff — состояние входа закрепляется за этим слотом.
4. Смена аккаунта: выделить слот → «Сбросить аккаунт» → запустить вход заново.
5. Общие сессии включены по умолчанию: при первом подключении спросят один раз, дальше все окна показывают одну и ту же историю.

## Как это работает

Freebuff — приложение на Electron, которое ограничивает себя одним экземпляром через `requestSingleInstanceLock()`. Инструмент **не меняет ни одного файла приложения**, а выдаёт каждому экземпляру собственный каталог данных:

- `--user-data-dir=<APPDATA>\Freebuff-slot-N` — отдельный профиль Chromium и отдельный лок блокировки;
- `FREEBUFF_DESKTOP_STATE_PATH=<user>\.config\freebuff-desktop\slots\slot-N\state.json` — отдельное состояние оркестратора (обходит его файловую блокировку SQLite);
- `~\.config\freebuff-desktop\slots\slot-N\projects\<работа>\desktop-v2.db` — локальная база сессий.

**Как работают общие сессии**: каталог `projects` каждого слота заменяется на junction (ссылку) к базе сессий главного экземпляра (`mklink /J`, права администратора не нужны; с v1.8.30 в первую очередь используется нативный `DeviceIoControl`, а `mklink` — только как запасной путь). Поэтому все экземпляры читают и пишут один и тот же `desktop-v2.db`, и история чатов общая «из коробки», а вход остаётся в каждом `state.json`, так что аккаунты не мешают друг другу. При первом включении существующая история сливается в главную базу, а прежний каталог переименовывается в `projects.pre-share-*` и остаётся как резервная копия.

Поэтому обновление самого Freebuff этот инструмент не ломает.

## Локализация

Freebuff при обновлении затирает результат локализации, и контроллер **сам** ставит его обратно в пяти случаях: версия установленного приложения изменилась, вы открыли контроллер, нажали «Запуск», отработал локальный `bash build.sh`, приехал новый пакет локализации под вашу версию. Перед заменой проверяется, что установленная версия английская или пакет новее, `targetVersion` совпадает с установленной версией и ни один слот не запущен; иначе шаг молча пропускается, а отложенный из-за работающих слотов попытка повторится через 10 секунд.

Замена файлов **сначала доводится до конца, потом переставляется**: файл целиком копируется в `ui.new-*` → проверяется, что все ресурсы из `index.html` на месте → два переименования на одном уровне → старый удаляется. В установленном каталоге в любой момент лежит либо старая целая копия, либо новая целая — состояния «контроллер thinks applied, а экран белый» не бывает. Если каталог признан неполным, он ставится заново.

Резервные копии английской версии хранятся только две последние целые (недописанные тоже удаляются), чистка идёт после каждого применения и через 1,5 секунды после запуска. Постоянной строки статуса в окне нет — события и прогресс появляются одной строкой под кнопками и исчезают через 8 секунд; постоянная информация живёт в подсказке трея.

Порядок поиска каталога локализации: `hanhua/` рядом с exe или уровнем выше → `freebuff-zh/` рядом или уровнем выше → вручную заданный путь `%APPDATA%\FreebuffController\hanhua-path.txt`.

Оффлайн-проверка (восстанавливает английский на время и сверяет возврат; сначала полностью закройте Freebuff): `bash tools/verify-autorestore.sh`

> В русской сборке пакет `hanhua/` не поставляется, поэтому этот раздел описывает оригинальное поведение и по умолчанию ничего не делает.

## Очистка кэша обновлений и `%TEMP%`

Официальный electron-updater копит установщики в `%LOCALAPPDATA%\@codebufffreebuff-desktop-updater\` (по замерам около 300 МБ), а пакеты, скачанные самим контроллером, лежат в `%TEMP%` (неустановленные становятся осиротевшими). Чистятся оба места, и **правило одно: установочный пакет удаляется, только если его версия не выше уже установленной**.

- Один раз **при запуске**, один раз **после каждого обновления** Freebuff (через 20 секунд — установщик часто ещё держит файл) и раз в **30 минут** как подстраховка.
- **Ожидающие установки обновления не трогаются**: пакеты новее установленной версии и тот, который записан в `pending-installer.txt`, остаются; `.exe` с нечитаемой версией тоже не трогаем.
- Корневой `current.blockmap` хранится всегда (нужен для дельта-загрузок); если удалить не вышло (занят / нет прав) — попробуем в следующий раз, на само приложение это не влияет.
- После уборки в строке под кнопками пишется, сколько освободилось; когда чистить нечего — молчит. **Кнопки «очистить кэш» нет**, автоматическая уборка и есть весь интерфейс этого механизма.

## Сборка

> Не хотите компилировать? Скачайте один файл exe из [Releases](https://github.com/Dima-Sor/freebuff-controller/releases).

Ставить SDK не нужно, хватает C#-компилятора .NET Framework, входящего в Windows:

```
build.bat
```

Исходник обязан быть совместим с **C# 5** (никаких `?.`, `$""`, `nameof`, expression-bodied members). Продукт сборки — это тот же самый exe, который сейчас запущен, поэтому **при работающем контроллере файл не записать**: сначала закройте его. После сборки прогоните оффлайн-самотест (самый рискованный путь с заменой файлов проверяется на поддельном дереве в temp, код возврата 0 — всё прошло):

```
FreebuffController.exe --self-test %TEMP%\selftest.txt && type %TEMP%\selftest.txt
```

Ожидается `BUILD OK` и `Всё ок (Всего 29 шт.)`.

Выпуск новой версии: поправить `AssemblyVersion` в `FreebuffController.cs`, затем `bash release.sh` (сборка + тег + загрузка).

```
├── FreebuffController.cs   # весь исходник (интерфейс + логика)
├── handover-merge.js       # скрипт миграции общих сессий (встраивается в exe при сборке)
├── CHANGELOG.md            # история версий оригинала
├── CHANGELOG-RU.md         # что изменено в русской ветке
├── build.bat               # сборка в один запуск
├── release.sh              # выпуск: сборка + тег + загрузка exe и sha512.txt
├── tools/
│   ├── embed-handover.py   # встраивает handover-merge.js в исходник перед сборкой
│   └── verify-autorestore.sh
└── app.ico                 # иконка приложения
```
